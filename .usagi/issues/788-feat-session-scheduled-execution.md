## 目的

定期的な作業を session として実行し、結果や失敗を後から確認できるようにする。
出典は 2026-10-16 に共有された対応候補一覧の項目 J。画像の評価は実現性「作れるが運用リスクあり」、規模「中」。
主な検討点は無人時の権限、実行の暴走、スリープ中の扱い。

## 対応範囲

- 実行内容、対象 workspace、Agent 設定、周期・時刻・タイムゾーンを持つスケジュールを登録できるようにする。
- 有効化・一時停止・削除と、次回実行予定・直近結果の確認を可能にする。
- 実行の権限と上限を事前に設定し、対話的な承認が必要な場合は待機を表示する。
- 前回実行が残っている場合の重複防止、実行時間・再試行・同時実行の上限を定義する。
- daemon 再起動や OS スリープ後の未実行回の扱いを決め、意図しない連続起動を避ける。

## 受け入れ条件

- [ ] 登録した予定から daemon が session の実行を管理し、結果を履歴で確認できる。
- [ ] 同じ予定回を再起動や再接続で重複起動しない。
- [ ] タイムゾーン・時刻変更・スリープ復帰・前回未完了時の挙動が定義され、表示で分かる。
- [ ] 権限不足や承認待ちを自動承認せず、失敗・待機の理由を確認できる。
- [ ] 利用者が将来の予定を停止でき、実行中 session の停止と区別できる。
- [ ] 注入した時刻と再起動を使って検証し、実装時に設定・daemon・TUI の仕様を更新する。
