## 目的

Agent の使用量と費用を把握し、利用状況を判断できるようにする。
出典は 2026-10-16 に共有された対応候補一覧の項目 E。画像の評価は実現性「Agent によって差がある」、規模「中」。
Agent ごとにログ形式が異なり、安定した共通の公開仕様がない点が主な課題。

## 対応範囲

- 対応 runtime ごとに取得可能な情報と情報源・形式の安定性を調査し、対応範囲を決める。
- 取得できる token 使用量や費用を Agent／session 単位で表示する。
- 実測値・推定値・未対応・未取得を区別し、期間・単位・最終更新を示す。
- 推定費用は model と料金情報の出典・適用時点を持ち、根拠がなければ金額を表示しない。
- resume や同じログの再読で使用量を二重計上しない。本文や秘密情報を集計のために保存しない。

## 受け入れ条件

- [ ] runtime ごとの取得方法・対応項目・制約が整理され、対応 runtime で値を表示できる。
- [ ] 未対応・取得失敗・推定をゼロや確定請求額として表示しない。
- [ ] Agent／session 集計の範囲と、再開時の重複排除が定義される。
- [ ] 料金またはログ形式の変化で解釈不能な値を黙って採用しない。
- [ ] 代表的なログ fixture・欠落・形式変化・再読をテストし、実装時に利用者向け仕様を更新する。
