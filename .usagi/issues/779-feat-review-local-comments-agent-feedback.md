## 目的

差分を読んだ場所で指摘を残し、担当 Agent への修正依頼と修正後の確認を一つの流れにする。
出典は 2026-10-16 に共有された対応候補一覧の項目 2。

## 対応範囲

- Diff の行または行範囲を選択してコメントを作成・編集・削除する。
- コメントを比較元・比較先の commit、ファイル、旧側／新側の行に結び付けて保存する。
- 送信前に指摘一覧と担当 Agent を確認し、一括で修正を依頼する。
- 配送は既存の agent_message と同じ durable な Agent 間通信を再利用する。人の TUI 操作からの送信者・宛先認可を設計し、MCP caller identity を偽装しない。
- 指摘ごとの未解決・修正報告あり・確認済みを表示し、Agent の修正報告だけで人の確認済みにしない。
- 差分更新で行が消えた場合は古い位置に誤って再配置せず、古い対象への指摘として確認できるようにする。

## 受け入れ条件

- [ ] 行／行範囲にコメントを付け、未送信の下書きを編集できる。
- [ ] 指摘の対象 commit・path・行・内容を含む依頼が選択した同一 session の担当 Agent に届く。
- [ ] 再送時に同じ送信 identity を使い、指摘や依頼が重複しない。
- [ ] 配送不能や Agent 不在では下書きを保持し、送信済みと誤表示しない。
- [ ] 修正後の差分と指摘を対応付けて確認でき、解決・再オープンを指摘単位で行える。
- [ ] 対象更新・再送・再起動時の状態をテストし、実装時に TUI と通信仕様を更新する。
