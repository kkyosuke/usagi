## 目的

TUI を開けない場面でも、ブラウザから session と Agent の進捗を確認できるようにする。
出典は 2026-10-16 に共有された対応候補一覧の項目 M。画像の評価は実現性「段階を踏めば可能」、規模「大」。
主な課題はブラウザ向けのアクセス経路と認証・認可の設計。

## 対応範囲

- 初期段階は読み取り専用とし、session／Agent の状態、PR／CI、対応待ちを表示する。
- まずローカル限定の閲覧経路を設計し、外部アクセスは認証・認可・暗号化の条件を満たす別段階に分ける。
- daemon を状態の正本とし、Web 側から worktree や機密ファイルを直接公開しない。
- 閲覧可能な workspace／session の範囲を定義し、credential・secret・内部の provider ID を公開しない。
- 取得不能・古い情報・切断を表示し、対象件数や応答サイズに上限を設ける。

## 受け入れ条件

- [ ] ローカルのブラウザで許可された session の状態と PR／CI・対応待ちを確認できる。
- [ ] 外部公開は既定で無効であり、段階ごとの認証・認可と公開範囲が設計される。
- [ ] 読み取り専用画面から Agent 起動・terminal 入力・削除・マージ等の変更操作を実行しない。
- [ ] scope 外の情報を返さず、HTTP の Origin／Host 検証を含む接続経路の保護を検証する。
- [ ] 切断・取得失敗・古い snapshot を正常または最新として表示しない。
- [ ] 表示・認可・機密情報の非公開を検証し、実装時に起動方法と公開条件を文書化する。

## 関連

操作の遠隔実行や terminal の全履歴公開は対象外。遠隔アクセスはローカル閲覧の検証後に分割して扱う。
