## 目的

危険領域やテスト確認が必要な変更をレビュー開始時に見つけやすくする。
出典は 2026-10-16 に共有された対応候補一覧の項目 5。

## 対応範囲

- recommend-tests.tsv の領域定義を利用して変更ファイルを分類し、分類規則を二重管理しない。
- IPC・永続化・coverage(off) に関する変更を強調し、該当した根拠を表示する。
- 実装変更に対応するテストの更新が見当たらない場合は、確認が必要な変更として示す。
- Rust の同一ファイル内テストや既存テストで確認できる変更も考慮し、「テスト変更なし」を即座に不備と断定しない。
- 未知の path や分類情報の取得失敗は分類不能として扱う。

## 受け入れ条件

- [ ] Diff のファイル一覧または要約から、領域別の変更と確認理由が分かる。
- [ ] IPC・永続化・coverage(off) の変更を識別し、対象ファイルへ移動できる。
- [ ] テスト更新の有無と判定根拠を示し、未知の領域を低リスクと誤表示しない。
- [ ] 分類定義の変更に追従でき、同じ差分に対する結果が安定する。
- [ ] この表示を CI や coverage の合否の代用にしない。
- [ ] 分類・未知 path・テスト同居ファイルをテストし、実装時にレビュー表示の仕様を更新する。
