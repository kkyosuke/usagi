## 目的

複数の session／terminal に分かれた出力から、エラーや確認したい文字列を探せるようにする。
出典は 2026-10-16 に共有された対応候補一覧の項目 F。画像の評価は実現性「条件付き」、規模「中」。
検索できる範囲は、メモリに保持されている出力に限られる。

## 対応範囲

- TUI が閲覧を許された、開いている workspace の保持中 terminal 出力を横断検索する。
- 検索対象の workspace／session／terminal と、保持範囲・対象外・取得不能を表示する。
- 結果に所属と前後の短い文脈を示し、該当 terminal の位置へ移動する。
- ANSI 制御列を検索語と混同せず、検索文字列・対象数・結果件数・処理量に上限を設ける。
- 出力追加・履歴切り捨て・terminal 終了時の検索結果の扱いを定義する。

## 受け入れ条件

- [x] 複数 terminal の保持出力を検索でき、結果の所属と一致箇所が分かる。
- [x] 過去の全履歴を検索できるように見せず、検索対象範囲と上限を表示する。
- [x] 一致なしと、未取得・検索不能・既に切り捨てられた結果を区別する。
- [x] 移動先の行が失われた場合に別の行へ誤移動せず、理由を表示する。
- [x] 大量出力でも TUI の入力を止めず、キャンセルと再検索ができる。
- [x] 検索・履歴切り捨て・対象消失をテストし、実装時に TUI の仕様を更新する。
